# Contributing

Thank you for considering a contribution to kuberoot. Contributions of every kind are welcome: code, package recipes, documentation, testing on hardware we do not have, reviews, bug reports and ideas.

## Before you start

- For anything larger than a small fix, open an issue first and describe what you want to change and why, so the design can be agreed before the work.
- New distributions and new packages are especially welcome. Tell us what problem the distribution or package solves.

## Pull requests

- Fork the repository, work on a branch, and open a pull request against `main`.
- Keep a pull request to one logical change. Several small pull requests are easier to review than one large one.
- Continuous integration must pass. Add or update tests for what you change.
- A maintainer reviews and approves the pull request before it is merged; see [GOVERNANCE.md](GOVERNANCE.md).

## Commits

- Write commit messages in the form `type(scope): description`, where type is one of `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `perf`, `build`. The message explains why the change is made; the diff shows what.
- Sign off every commit (`git commit -s`) to certify the [Developer Certificate of Origin](https://developercertificate.org/): that you wrote the change or otherwise have the right to submit it under the project's license.

## AI-assisted contributions

Contributions made with the help of AI tools are welcome, on the same terms as any other: you are responsible for the change, you understand it, and you can explain and maintain it. Mark such commits with an `Assisted-by:` trailer naming the tool.

## Language

Code, comments, commit messages, pull requests, issues and documentation are in English. Where a document has a Russian copy (`*.ru.md`), the English one is primary.
